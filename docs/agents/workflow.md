# Git and agent workflow

## Repository model

The Git root is the local **MDK-1.2.5** folder. Only allowlisted original project files are committed. `main` represents the last deliberately accepted project baseline, while individual features should normally use scoped branches.

## Recommended workflow

```powershell
git status --short
git pull --ff-only origin main
git switch -c feature/foundry-multiblock
# edit and validate project files
git diff --check
git diff
git add -- src/minecraft/zed docs zto-tools
git diff --cached --name-only
git diff --cached
git commit -m "feat(foundry): add structure validation"
git push -u origin feature/foundry-multiblock
```

For a documentation-only task, use a `docs(...)` commit. For language/comment-only changes use `chore(...)` and preserve behavior. Keep commits focused; do not combine refactors, game mechanics, large autogenerated files and docs in one unreviewable change.

Use pull requests to review feature branches before merging. Include precise testing evidence, limitations and any save-compatibility implications in the PR description.

## Task handoff

At the end of an agent session, report:

- Relevant commit/branch and changed paths.
- Exactly what was implemented.
- Exact checks executed, plus anything not tested.
- Known risks and next recommended task.
- Any changed block IDs, recipes, NBT formats or EMC values.

Do not claim that a tool edited the user's local Windows files merely because it committed to GitHub. The owner must `git pull` before local Eclipse sees remote changes.

## Language

Conversations can be in Italian; **everything saved into Git must be in English**, including docs, code comments, diagnostics, scripts, commit messages and PRs. Keep existing stable public API names unchanged unless explicitly asked to rename them.
