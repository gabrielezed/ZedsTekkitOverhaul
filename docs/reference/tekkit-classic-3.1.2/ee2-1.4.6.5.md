# Equivalent Exchange 2 reference — version 1.4.6.5

**Status:** selected declarations were checked against the user's supplied decompilation of `EE2ClientV1.4.6.5.jar` and the **existing ZTO integration source**. Unlike IC2, no version-specific, separately distributed public EE2 SDK has been verified. Treat the following as **observed implementation hooks**, not a promise of a stable public API.

## Confirmed EMC entry points

The following exact signatures are visible in EE2 1.4.6.5:

| Class | Member | Meaning |
| --- | --- | --- |
| `ee.EEMaps` | `static int getEMC(int itemId, int metadata)` | Returns the stored mapping; returns 0 when missing |
| `ee.EEMaps` | `static int getEMC(int itemId)` | Convenience lookup for metadata 0 |
| `ee.EEMaps` | `static void addEMC(int itemId, int metadata, int emc)` | Writes the mapping, **including overwrite** |
| `ee.EEMaps` | `static void addEMC(int itemId, int emc)` | Convenience mapping for metadata 0 |
| `ee.EEBase` | `static boolean externalModsInitialized` | Integration-initialization flag used by ZTO |
| `ee.EEItem` | `alchemicalCoal`, `mobiusFuel`, `aeternalisFuel` | Public item fields resolved by ZTO |

**Semantics actually observed:** `addEMC(int,int,int)` stores into an internal metadata-indexed map and **does not reject an existing value**. It logs when asked to store a zero EMC. This is why our integration checks `getEMC(...)` and only writes **missing** values.

A missing zero entry must not automatically be interpreted as safe for every item; metadata, damage values and EE2's own special item handling may affect the design. Validate complex conversions in the real game.

## Existing ZTO integration lifecycle

- `EE2ItemResolver` resolves the three fuel fields by reflection, without EE2 at compile time.
- `EE2FuelIntegration` returns the legacy furnace burn time to ModLoader; this is used by the IC2 Generator integration.
- The [ZTO EMC module](../../engineering/emc-profile.md) waits for `externalModsInitialized` on the game tick before applying its compatibility defaults or an explicit profile.
- Intended values are **128 EMC** for Advanced Crafting Table and **16 EMC** for Foundry, *provided the runtime does not already assign a value*.
- `IC2EmcIntegration` is a separate experimental integration and is currently **disabled**.

### Suggested integration invariants

1. Never override an existing positive EE2 value by default.
2. Use exact numeric ID and metadata; avoid assuming all subtypes share metadata 0.
3. Run once after EE2's external initialization; avoid repeated map writes during ticks.
4. Handle absence of EE2 cleanly in plain MCP development.
5. Validate EMC before and after recipe registration; identify possible positive EMC/EU feedback loops.
6. Record balancing rules separately from implementation details.

## Compatibility and packaging

Original EE2 1.4.6.5 production JARs contain obfuscated Minecraft references; putting them directly into a deobfuscated MCP `jars/mods` is known to cause errors such as `NoClassDefFoundError: forge/IConnectionHandler`. Reflection has been sufficient for the existing optional integration. Do not add decompiled `ee/` classes, copies of EE2 or proprietary binaries to this repository.

External archive index: [MCArchive EE2 1.4.6.5](https://mcarchive.net/mods/ee2?gvsn=1.2.5). The archive index is for provenance, **not** a claim that an independent supported EE2 API exists.
